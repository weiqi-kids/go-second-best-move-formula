# 圍棋次佳手公式不存在性——Scrollytelling D3.js 互動網頁設計

**日期**：2026-05-01
**狀態**：approved

---

## 1. 專案目標

將「圍棋第二好的次一手公式不存在性的完整證明」（readme.md）做成一頁式 D3.js 互動網頁，讓完全不懂圍棋也不懂計算理論的高中生能理解核心論證。

## 2. 設計決策摘要

| 決策 | 選擇 | 理由 |
|------|------|------|
| 呈現深度 | 混合版（科普主線 + accordion 數學細節） | 兼顧快速理解與深入探究 |
| 頁面形式 | Scrollytelling 長卷軸 | 沉浸感最強，適合講故事 |
| 語氣風格 | 知識型 YouTuber + 教科書科普 | 有熱情但保持知識密度 |
| 語言 | 中英混合（解說繁中，專有名詞英文） | 平衡可讀性與精確性 |
| 目標受眾 | 不懂圍棋、不懂 CS 的一般高中生 | 最大覆蓋面 |

## 3. 技術棧

- **單一 HTML 檔案**（`index.html`），自撰 CSS/JS 內嵌，第三方庫經由 CDN 以 `<script>` 標籤載入
- **D3.js v7**（CDN）：所有互動圖表
- **Intersection Observer API**（原生）：滾動觸發
- **MathJax 3**（CDN）：數學公式渲染
- **CSS Custom Properties**：OKLCH 色彩 + hex fallback（依 design-tokens）

### CDN 規範

- D3.js：`https://cdn.jsdelivr.net/npm/d3@7.9.0/dist/d3.min.js`（integrity hash 鎖定）
- MathJax：`https://cdn.jsdelivr.net/npm/mathjax@3.2.2/es5/tex-mml-chtml.js`（integrity hash 鎖定）
- 每個 `<script>` 標籤加 `integrity` 與 `crossorigin="anonymous"` 屬性

### CDN 降級策略

- `<script>` 標籤加 `onerror` 處理：CDN 載入失敗時顯示靜態 fallback 訊息（「互動圖表載入失敗，請檢查網路連線」）
- MathJax 載入失敗時，LaTeX 公式以原始文字顯示（`<noscript>` 或 CSS fallback）
- 建置時可考慮 bundle 選項（將 D3/MathJax 內嵌）作為替代部署方案

### 效能策略

- 圖表採延遲初始化（lazy init）：Intersection Observer 偵測到圖表容器進入視窗前 200px 時才呼叫對應的 D3 繪製函式。初始化期間顯示骨架屏（skeleton）或 spinner +「載入中...」文字，完成後淡入替換。
- 圖表採銷毀/休眠（teardown）：離開視窗超過 2 屏後，將 SVG 內容移除（保留容器高度以免版面跳動），重新進入時重繪。
- 同時存在於 DOM 的活躍 SVG 圖表不超過 3 個。
- 所有 `<script>` 區塊依章節拆分為 IIFE，避免全域命名空間汙染。

## 5. 故事線與各章內容

### Hero

- 大標題：「圍棋的『第二好的一手』——為什麼不存在捷徑？」
- 副標題：「一個業餘棋手的直覺問題，如何通往計算理論的深處」
- 視覺：使用 D3 繪製的 9×9 棋盤，預設 7-8 顆黑白子散落。頁面載入時棋子依序淡入（`duration(400)`, `delay(i * 100)`）。不設互動（純裝飾）。

### Chapter 0：棋手的疑問

科普語氣帶入情境。不預設讀者懂圍棋。

> 「想像你在玩一個遊戲。你知道有一個『最佳選擇』，但算不出來。退而求其次，你想：第二好的選擇是什麼？能不能用一個公式直接算出來，不用把整盤棋從頭到尾模擬一遍？」

### Chapter 1：什麼是圍棋？

為完全不懂圍棋的讀者鋪陳。三個 step：

1. 棋盤是什麼（19×19 格線、黑白交替落子）
2. 怎麼吃子（氣的概念）
3. 怎麼算輸贏——圍地計分。數你圍住的空交叉點（目），減去對方圍的。**重點：分數一定是整數**（每個空點要麼歸你、要麼歸對方、要麼是中立點）。這個看似平凡的事實，後面會成為關鍵武器。

### Chapter 2：用數學描述問題

對應原文 §1.2–§1.7。四個 step：

1. 一個「局面」就是棋盤的一張快照——記錄三件事：(1) 每個交叉點上有黑子、白子、還是空的；(2) 輪到誰下；(3) 哪裡不能立刻下（劫禁點）。就這三樣東西，完整描述了一個圍棋局面。
2. 「最好」= minimax——你選最大，對手選最小
3. 「第二好」= 排除最佳手後的冠軍
4. 「公式」= 不用暴力搜尋的捷徑，精確定義為 poly(n) 時間。這裡有一個關鍵前提：圍棋的計分是整數（每個空交叉點值 1 目），所以 Q 值一定是整數。

### Chapter 3：計算的極限

為完全不懂 CS 的讀者介紹複雜度。三個 step：

1. P 是「快速能解的問題」、EXPTIME 是「慢到不行的問題」
2. P ⊊ EXPTIME（已證明！給更多時間確實能解更多問題）
3. 圍棋是 EXPTIME-complete——它能模擬任何超級慢的計算。「圍棋不只是一個遊戲——數學家發現，你可以把**任何**超級複雜的計算問題『翻譯』成一盤圍棋。這就像圍棋是一種『通用程式語言』——如果你能秒解圍棋，你等於能秒解世界上所有超難問題。」

### Chapter 4：為什麼 Q 沒有公式（定理 A）

核心論證的科普化。兩個 step：

1. 若 Q 有 poly 時間公式 → 圍棋變「快速可解」→ EXPTIME ⊆ P → 矛盾！日常類比：「假設你有一台能秒算任何圍棋局面價值的神機——這台機器不只是圍棋作弊器，它等於能解開宇宙間所有超難問題（因為圍棋能模擬任何超難計算）。但數學已經證明：這種萬能機器不可能存在。所以神機不存在，公式也不存在。」
2. 近似也不行——因為目差是整數，四捨五入就回到精確值。只要你的近似誤差小於 0.5，取整就能完美恢復精確答案。所以「0.49 的近似」就已經等同精確。

### Chapter 5：空間壓縮的巧妙（定理 B）

原文最有創意的部分。三個 step：

1. 為什麼不能直接證明 m₁ 的困難？這裡有一個深層原因——任何 EXPTIME-complete 的博弈，其對弈長度必然是超多項式的（否則 minimax 搜尋就能在 PSPACE 中完成，與 EXPTIME-complete 矛盾）。這代表「沿著最佳對弈走到底」的策略，在時間上注定走不完。這不是圍棋的特殊問題，而是所有「超級難」博弈的共同宿命。（元定理：博弈長度障礙的內蘊性）
2. 空間壓縮的洞察：不需要走完，只需要記得「現在在哪」（遊忘模擬）
3. 龜兔賽跑偵測循環——Floyd 算法的直覺

### Chapter 6：次佳手也不行（定理 C+D）

四個 step：

1. 定理 C：若次佳手有公式 → 最佳手也有公式 → 塌縮（二元分支的巧妙）。日常類比：「這就像只有兩間教室 A 和 B，你知道數學課在其中一間。如果有人告訴你體育課（次佳手）在 B 教室，你立刻就知道數學課（最佳手）在 A 教室。所以知道第二名就等於知道第一名。」
2. 瓶頸構造直覺：「想像三個房間 D、A、B。D 裡有一顆巨大的炸彈（n⁴ 子的群），你一定要先去拆彈（m₁=d）。拆完彈之後，第二重要的事（m₂）在 A 還是 B——取決於 ATM 是否接受。」
3. 接受方向：ATM 接受 → A 有好手 → m₂ 在 A。
4. 拒絕方向：ATM 拒絕 → A 全部是壞手 → m₂ 只能在 B。

### Chapter 7：更廣的視野（定理 E+F）

兩個 step：

1. 定理 E——查表也不行（非均勻版本）。「有人可能想：我不用通用公式，我直接把每個局面的答案背下來呢？這就是『電路複雜度』的範疇——結論是，除非我們對數學的基本信念有誤，連這種超級大的查表也行不通。」
2. 定理 F——那 19×19 到底怎樣？「壞消息是查表公式理論上存在（因為 19×19 局面數有限），好消息是⋯⋯其實也是壞消息：我們根本無法判定是否存在一個『短小精悍』的版本。這個問題碰到了數學的三重鐵壁（相對化、自然證明、代數化）。」

### Chapter 8：全景總覽

一個 step：定理 A–F 的完整地圖，邏輯依賴關係，條件強度

## 8. 互動行為與動畫規範

### 8.1 Scrollytelling 機制

- Intersection Observer 對每個 step 設置 `rootMargin: "-40% 0px -40% 0px"` 搭配 `threshold: 0`，以視窗中央 20% 帶為觸發區，避免多 step 同時 active。
- Step 切換時觸發 D3 transition。
- Active step 不透明度 1.0，其餘 0.3。
- Step 間距：≥1024px 60vh；768–1023px 40vh；<768px 30vh（與 §7.4 斷點一致）。
- 加入防抖（debounce）：快速滾動時不連續觸發 D3 transition，僅在滾動停止後 100ms 觸發。

### 8.2 D3 動畫時序

### 常見反駁 FAQ（置於 Chapter 8 末尾，Footer 前）

以 accordion 形式呈現：
- **「那 AlphaGo/KataGo 不是做到了嗎？」**：近似不等於精確。KataGo 提供的是啟發式估計（勝率、目差近似），會犯錯，且無精確度保證。本文的「公式」要求對所有局面精確輸出 m₂，不允許任何錯誤。
- **「那量子電腦呢？」**：量子電腦能力（BQP）仍在 PSPACE 以內，遠不及 EXPTIME。量子加速不足以攻破圍棋的計算複雜度壁壘。
- **「那圍棋收官公式（CGT / 溫度圖）不是存在嗎？」**：CGT 收官公式適用於可分解的局部終盤（獨立區域之間無交互作用），與本文的全局不存在性結論不矛盾。本文證明的是：對所有合法局面（包括中盤、劫爭糾纏等不可分解的情況）不存在通用公式。

### 8.5 無障礙

- **圖表語義**：每個 SVG 加 `role="img"` + `aria-label`（一句話摘要）+ `<desc>`（完整文字描述，涵蓋圖表傳達的核心資訊）
- **動態更新**：圖表容器加 `aria-live="polite"`，step 切換時更新 `aria-label`
- **動畫偏好**：實作 `@media (prefers-reduced-motion: reduce)`，所有 transition duration 設為 0，自動播放動畫改為靜態最終狀態
- **自動播放**：提供暫停/重播按鈕，`aria-label="暫停動畫"` / `"重播動畫"`
- **鍵盤操作**：Slider 可用 Arrow Keys 操作；拖曳元素可用 Arrow Keys 移動；Tab 鍵可在互動元素間導航
- **Focus indicator**：所有互動元素的 `:focus-visible` 加 `outline: 3px solid var(--color-link)` + `outline-offset: 2px`
- **Accordion**：按鈕加 `aria-expanded="true/false"` + `aria-controls="panel-id"`
- **對比度**：所有文字/背景組合符合 WCAG AA（正文 4.5:1，大字 3:1）
- **Skip link**：頁面頂部加「跳至主要內容」連結
- **語言標記**：`<html lang="zh-Hant">`，英文專有名詞段落使用 `<span lang="en">` 標記
- **螢幕旋轉**：`resize` / `orientationchange` 事件觸發時，debounce 300ms 後重新計算圖表尺寸（SVG `viewBox` 不變，容器重排），重新評估 Intersection Observer 的 active step
